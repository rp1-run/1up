## Root cause and repair evidence

1. A fake `codex_path_override` integration test records final argv and proves
   that workspace-bound oneup MCP overrides are present only on the 1up target,
   never on the baseline or distinct Codex grader.
2. Search Stack attempts 1-3 received the expected argv but exposed no oneup
   tools. Making the server required in attempt 4 surfaced the concrete error:
   `required MCP servers failed to initialize ... connection closed`.
3. Exact-environment reproduction captured the server's stderr:
   `path contains a symlinked component: /tmp`. The fixture harness used the
   hard-coded `/tmp/1up-evals`, while macOS resolves `/tmp` through a symlink.
4. Fixtures now use `realpathSync(tmpdir())/1up-evals`. A direct initialize
   request then returned a valid MCP response, and live Search Stack runs kept
   the `1up mcp` child alive for the model turn.
5. The oneup server is required with an explicit startup timeout. Apps/plugins
   are disabled only on the 1up target, and non-prefixed local MCP tool names
   are enabled there. Baseline and grader remain isolated.
6. Codex raw-item normalization now treats `error: null` as success and matches
   the Rust `ToolEnvelope` contract where `NextAction.arguments` is optional.
   Missing, invalid, or genuinely failed oneup calls still fail closed.
7. Fixture cleanup now stops the workspace daemon with the same isolated home
   before removing the workspace, preventing orphaned eval-owned workers.

The reviewer control smoke advertised all nine oneup tools and remained
protocol-clean, but its fresh fixture finished degraded and missed the expected
search hit. That control failure is retained separately and is not represented
as an all-pass server smoke.
