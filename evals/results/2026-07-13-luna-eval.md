## Contract changes

- `prompt-1up.txt` now requires symbol verification for the central symbol the
  agent actually discovers. It no longer biases every task toward
  `FTSManager` or `searchWithDb`.
- Plugin Architecture now distinguishes trusted in-process registration and
  hook execution (`PluginManager` and `HookPipeline`) from the separate
  sandbox descriptor/runtime path (`PluginManifest`, `SandboxRunner`, Worker
  Loader wrapper, and capability-checking bridge).
- Live Content Query now asks for the public Astro live-collection path:
  database-backed schema, `_emdash` registration with `emdashLoader()`,
  `LiveLoader` query translation, and typed public query helpers. It explicitly
  distinguishes that path from internal `ContentRepository.findMany` queries.
- The impact trust assertion now requires both an associated primary/direct
  higher-confidence boundary and an associated contextual/indirect
  lower-confidence boundary. A lone keyword no longer passes. The 1up impact
  prompt fairly requests those two explicit sections for every impact task.

These are shared task and rubric corrections grounded in the emdash fixture at
`5beb0dd`; neither provider receives variant-specific answer hints.
